# Code of Conduct

## The short version

Be straightforward and be decent. Argue about the code and the maths, not about
the person writing them.

## What is expected

- **Critique the work, not the author.** "This interval is wrong because the
  strikes are not independent" is useful. "You clearly don't understand
  econometrics" is not, and is also usually incorrect.
- **Assume people are here in good faith.** Contributors come from very
  different backgrounds. Someone who knows React and no option pricing, or
  option pricing and no React, is exactly the kind of contributor this project
  wants.
- **Questions are not a burden.** If something in the methodology is unclear,
  the documentation is at fault before the reader is. Asking makes the project
  better.
- **Accept that being wrong is normal.** The maintainer has shipped a bubble
  estimate described as a probability, and a bound derived in the wrong
  direction. Both were caught and fixed. That is the process working.

## What is not acceptable

Harassment, personal attacks, demeaning comments about someone's background or
identity, deliberately derailing discussions, and publishing anyone's private
information. Also: presenting confident financial claims you have not checked,
in a repository whose entire point is that unverified claims are how people get
this subject wrong.

## Scope

This applies to issues, pull requests, discussions, commit messages and code
review in this repository.

## Enforcement

Report a problem to the maintainer at lukaadz@upenn.edu. Reports stay
confidential. Responses range from a request to edit a comment through to a
block, depending on severity and whether it is repeated.
